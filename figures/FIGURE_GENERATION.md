# Figure Generation Guide

This document describes how each panel of every manuscript figure is
generated, which input files it consumes, and where its outputs land.

Each manuscript figure has its own self-contained directory under
`figures/figure_<n>/` with the same layout:

```
figures/figure_<n>/
├── generate_figure_<n>.py           # orchestrator: runs every panel script
├── generate_figure_<n>_panel_*.py   # one script per panel (or panel group)
├── data/                            # inputs consumed by the panel scripts
└── output/  or  outputs/            # PNG/SVG/PDF panel outputs (gitignored)
```

The orchestrator scripts (`generate_figure_<n>.py`) launch each panel
script as a subprocess. They are also the entry points used by the
top-level `run` script. The final multi-panel figures were assembled in
Inkscape from the SVG outputs; this repository does not include the
Inkscape composition step.

All paths in panel scripts are relative to the script's own directory,
so each figure can be regenerated by `cd`-ing into `figures/figure_<n>/`
and running its orchestrator. A handful of panels also reach back into
the repo-level `data/` tree for raw inputs that are too large to bundle
locally — those are flagged below.

---

## Top-level orchestration

To regenerate every figure that has bundled data:

```bash
bash run
```

This executes each `figures/figure_<n>/generate_figure_<n>.py` in turn
and copies its outputs into `outputs/figure_<n>/` at the repo root. See
the top-level `README.md` for setup details.

**Panel A.** Clustermap of mean spatial features for each Leiden cluster
(rows) of the ABM state space, with rows colored by the six TME states

**Panels B–E.** Each panel is a UMAP scatter colored by a different
quantity:
- **B** — UMAP colored by TME state label (1–6)
- **C** — UMAP colored by simulation time
- **D** — UMAP overlaid with three highlighted simulation trajectories
  (sim_044, sim_100, sim_028)
- **E** — Four UMAPs colored by individual cell-type proportions and
  malignant epithelial degree centrality

**Panel F.** Bokeh snapshots of representative ABM time points for each
of the six TME states, rendered with BioRender cell-type icons. The
snapshot HTMLs/PNGs are exported individually and assembled into a
single panel SVG in Inkscape.

> **Panel F note:** This panel reads raw PhysiCell simulation folders
> (`data/abm/raw/sim_<id>/`) and BioRender icon PNGs from the repo
> root. Neither is bundled into `figures/figure_2/data/`; both must be
> obtained separately (Zenodo for the simulations; BioRender icons are
> the authors' research-use license assets). The panel script catches
> per-snapshot failures so the run script does not abort.

## Reproducibility tips

- **Marimo notebooks** (`generate_figure_2_panel_f.py`,
  `generate_figure_3_panel_b_mibi.py`,
  `generate_figure_3_panel_b_imc.py`,
  `generate_figure_3_panel_d.py`,
  `generate_figure_6_panel_e_and_f.py`) end with
  `if __name__ == "__main__": app.run()` so they execute as plain
  Python scripts using the default cell values. To explore alternative
  selections, open them with `marimo edit <script>`.
- **Fonts** — All scripts set `plt.rcParams['svg.fonttype'] = 'none'`
  so SVG outputs reference system fonts. Inkscape will render them
  cleanly if the font (default sans-serif) is installed.
- **Optional style** — Panels look for the `forest_and_sky_academic`
  matplotlib style and fall back to `default`/`ggplot` if it is not
  installed. The style is not required to reproduce the figures.
- **Headless PNG export (Figure 2 Panel F)** — Bokeh's `export_png`
  needs a headless browser plus driver. The script falls back to HTML
  output if the driver is missing. To enable PNGs:
  `conda install -c conda-forge firefox geckodriver`.
